## Scope and resolved gaps

- Layers 0--5 are the Mac map; Layers 6--11 are the matching Windows map.
  Every layer has exactly 82 physical bindings.
- The physical Win-switch contact at Layer-0 position 77 remains
  `&mo LYR_W_BASE`; Layer 6 is `LYR_W_BASE`, not `LYR_W_FUNC`.
- Layer 4 / `LYR_M_UAT` and Layer 10 / `LYR_W_UAT` are fully defined:
  position 0 exits to their OS base and positions 1--81 are inert.
- Layer 5 / `LYR_M_MCRO` and Layer 11 / `LYR_W_MCRO` are fully defined:
  Esc exits; number-row positions 15--18 persistently select Function,
  Symbols, Navigation, and UAT for their own OS; all other positions are inert.
- F6 on both Function layers is `Ctrl+Alt+M` (`&uc LC(LA(M))`).
- The SYM1 O and P positions (37 and 38) are named tap dances for `-/_` and
  `=/+`; positions 39--41 are transparent. No placeholder remains.
- Windows Navigation position 59 is `Ctrl+V` (`&uc LC(V)`); Mac and Windows
  Navigation position 22 (the physical 8 key) sends Space (`&kp SPACE`).
- Esc’s 600 ms hold now uses ordinary `&kp` press/release bindings rather than
  `&kt`. This removes the retained Caps key state that made users perform two
  holds to complete a toggle.

## Behavior and code-file delta

- Candidate-only additions: `TD_SYM_MINUS_UNDERSCORE`, `TD_SYM_EQUAL_PLUS`,
  Windows Layers 7--11, and physical-layout comments for every Windows layer.
- Candidate-only correction: `esc_caps` preserves its 600 ms `tap-preferred`
  policy but now uses `bindings = <&kp>, <&kp>;`; no quick-tap state is kept.
- Validation: `scripts/validate-v0.23-keymap.ps1` locks this source hash,
  checks all 12 layer names and 82-binding sizes, verifies direct controls,
  selectors, resolved diagram anchors, and rejects placeholders.
- The B1 Pro vendor source required a fixed-keymap integration change because
  its normal Launcher dynamic-map allocation cannot represent 12 layers and
  its support objects are also used by 24G/BLE/macro code. The change is
  limited to these files:
  - `app/Kconfig`: adds `ZMK_LAUNCHER_FIXED_KEYMAP`, an opt-in fixed-keymap
    mode for the vendor support objects.
  - `app/boards/shields/keychron/b1/us/keychron_b1_us.conf`: enables that mode
    for this B1 Pro shield.
  - `app/src/launcher/launcher.h`: restricts the otherwise inactive dynamic
    buffer to one layer in fixed-keymap mode, avoiding the 12-layer EEPROM
    allocation assertion.
  - `app/src/launcher/launcher.c`: returns before registering the Launcher HID
    endpoint or initializing/loading dynamic maps in fixed-keymap mode.
- Safety impact: the compiled firmware retains the vendor utilities required
  by B1 Pro 24G/BLE/macro code, but does not expose Keychron Launcher over USB
  or mutate the reviewed ZMK keymap from a dynamic-map store. v0.23 therefore
  provides no Keychron Launcher, VIA, or Vial configurator support.
- No shared ZMK behavior, DTS, board, or shield-overlay source changed.
